# Индекс страниц

## Порядок блоков проекта

`projects.blockOrder` хранит индивидуальную перестановку. Заголовки блоков перетаскиваются; кнопки вверх/вниз обеспечивают управление с клавиатуры. Главный экран закреплён первым и не входит в сохраняемый порядок. Описание для каталога и поиска также не входит в порядок визуальных блоков.

Обычное сохранение меняет только текущую запись. «Применить порядок ко всем» атомарно обновляет порядок существующих записей и `pages.layout` шаблона проекта; новые записи наследуют порядок шаблона. Тип записи продолжает определять, какие блоки отображаются. Общие хедеры и футер остаются в оболочке сайта.

Публичный маршрут `/catalog/[slug]` получает порядок через `/api/projects/page-order?slug=...`, без кеширования. Этот публичный endpoint возвращает только известные ключи блоков. Перестановка отражается в превью до сохранения; при недоступности CMS сайт использует исходный порядок. Остальной контент публичного сайта пока берётся из исходных TSX и каталога, а не из CMS.

Общие элементы оболочки входят в `pages.layout` как ссылки на единые записи: технический хедер, основной хедер и футер. У блока есть `parts` — именованные элементы его состава. В раскрытой строке структуры состав показан списком; выбор элемента переключает изолированное превью. Главный экран содержит заголовок, подзаголовок, кнопку, промо-группу и отдельные промо-слоты с названиями из исходников.

После импорта для дополнения существующих страниц выполнить из `cms` команду `npm run structure:complete`. Она читает исходники публичного сайта из соседнего `src`, добавляет отсутствующие общие ссылки, сохраняя существующие строки, маршрут и title. Повторный запуск не дублирует хедеры и футер. Локально миграция и дополнение уже выполнены. Переадресации не получают визуальную оболочку.

Раздел `/structure/pages` читает редактируемые записи коллекции `pages` из PostgreSQL. Нажатие на название открывает редактор Payload. `src/data/site-index.json` служит только источником первоначального импорта; ручные правки хранятся в БД.

Первоначальная настройка из директории `cms`:

```powershell
npm run migrate
npm run import:site
```

Локально эти команды уже выполнены. Для других окружений миграции необходимо применить до запуска обновлённой CMS.

Коллекции `blocks` и `forms` содержат реестр разработанных компонентов: ключ, исходный файл, экспорт, параметры по умолчанию. Запись блока связывается со встроенными формами. `pages.layout` — упорядоченный массив ссылок на эти две коллекции, с якорем и параметрами экземпляра. Из редактора страницы нельзя создавать компонент: его сначала регистрируют в соответствующем разделе. Новый компонент требует разработки и подключения к рендереру в коде; регистрация сама по себе не создаёт реализацию.

Импорт добавляет только отсутствующие записи. Скрытый `importKey` сохраняет соответствие исходному маршруту после ручного изменения адреса. Название, title и структура существующей страницы повторным импортом не перезаписываются.

Публичный сайт пока использует исходные TSX-маршруты и компоненты. Изменения в CMS сохраняются, но ещё не меняют публичный рендеринг. Начальный импорт переносит непосредственно используемые компоненты страниц и структуру главной; встроенная в TSX разметка и условные ветви требуют дальнейшего переноса в самостоятельные блоки. Параметры импортированных блоков пока представлены JSON, специализированные редакторы параметров ещё не подключены.

В «Страницах» карточки проектов представлены одним шаблоном `/catalog/[slug]`. Индивидуальные записи вынесены в `/structure/catalog`: название, технология, площадь, этажность, спальни, санузлы, описание, базовая цена и ссылка на проект. В полном индексе конкретные адреса проектов сохранены для проверки покрытия маршрутов.

Из корня репозитория обновить индекс:

```powershell
npm run index:site
```

При запуске публичного сайта через `npm run dev` и его сборке индекс обновляется автоматически. После изменения маршрутов или каталога обновлённый JSON нужно включать в коммит для CMS.

Индексатор читает все `src/app/**/page.tsx`, разворачивает карточки проектов из `CATALOG_PROJECTS` и выставочные площадки из `EXPOSITION_PLACES`. Неизвестный динамический маршрут, отсутствующее название и повторяющиеся адреса завершают индексацию ошибкой. Параметры поиска и фильтров не считаются самостоятельными страницами. Переадресации и предпросмотр остаются отдельными типами маршрутов. Для `/mortgage` записан адрес программы по умолчанию; фактическое назначение зависит от параметра `program`.

Для каждой страницы сохранены исходный файл, компоненты, непосредственно используемые в JSX этого файла, и явно заданные идентификаторы секций. Условные компоненты перечислены как возможные; это не снимок отрисованного DOM и не готовая модель редактируемых блоков. Пять серверных обработчиков сохранены отдельно в `services`, в таблицу страниц они не включаются.

Адрес публичного сайта для кнопки открытия определяется `SITE_PUBLIC_URL`; по умолчанию локально — `http://localhost:3000`, в production — `https://new.avgst.ru`.
# Карточки каталога

Записи `projects` содержат данные конкретного проекта или готового дома. Поле `recordType` различает `project` и `ready-home`; технология и серия выбираются из закрытых списков. Каталог фильтруется по типу записи. Для готового дома показывается цена продажи, для проекта — базовая цена.

Редактор следует порядку шаблона `/catalog/[slug]`: главный экран → фасады → планировки → интерьеры → построенные дома → ипотека и комплектации / условия продажи готового дома. Описание для каталога и поисковых систем вынесено отдельно. Галереи, экспликации, видео, опции и условия готового дома импортируются из исходных записей без повторного перезаписывания редакторских изменений (`contentImported`). Команда `import:site` требует полного репозитория, поскольку читает `src/lib/catalog/projects.ts`.

Справа используется тот же эмулятор устройств, что в редакторе страниц. Раскрытие секции выбирает соответствующий блок в превью. Превью отображает текущую публичную версию сайта: сохранение контента в CMS пока не меняет публичный источник данных. Структура страницы, общие хедеры, контакты и футер редактируются в шаблоне, а не в записи каталога.
