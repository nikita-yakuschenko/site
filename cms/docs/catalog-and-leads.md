# Ручное наполнение каталога

Проекты создаются по одному в CMS. После сохранения название, адрес, характеристики и загруженное главное изображение попадают в каталог и на `/catalog/<адрес>`. Привязка к исходному моковому списку или ключ импорта не нужны. Комплектации выбираются по технологии, их описания общие. Пока цена не загружена, сайт показывает «Цена уточняется».

«Описание для поиска» по умолчанию повторяет название проекта. Редактор может ввести собственный текст или вернуться к названию кнопкой в поле. Это описание используется в метаданных страницы.

# Отправка форм

В разделе «Интеграции» доступна настройка «Отправка заявок» и журнал отправок. Настройки меняет суперадмин. Режимы: отключено, тестовый обработчик, API / вебхук.

Форма вызывает `/next/leads`. Сервер сайта проверяет данные и передаёт их защищённому обработчику CMS. CMS выбирает механизм по настройкам интеграции. В тестовом режиме обращение сохраняется в журнале без внешнего запроса. В режиме API / вебхука выполняется POST с JSON `{id, lead}` и заголовком `X-Request-ID`. Необязательный Authorization берётся из указанной серверной переменной окружения; токен не передаётся браузеру.

Данные обращения содержат форму, адрес страницы, идентификатор проекта, название и адрес проекта, выбранный регион и параметры расчёта, если форма относится к калькулятору. Ответ об успехе появляется только после приёма обработчиком. Ошибки передачи отмечаются в журнале и возвращаются форме.

В production отправка по умолчанию отключена. Локальный тестовый режим позволяет проверять формы без подключения реальной CRM.
