# SmartCaptcha: аудит и исправления — 25.10.2026

## Подтверждённые причины

1. `LeadForm` запрашивал конфигурацию при монтировании каждой формы и создавал
   `InvisibleSmartCaptcha` без попытки отправки. После попытки `key={captchaReset}`
   создавал следующий скрытый экземпляр. Production-проверка обнаружила один
   виджет на странице и два после открытия диалога до отправки.
2. Отмена опиралась на общий mutable pending callback; отложенное событие закрытия
   могло затронуть другую попытку. Таймеры и конфигурационный запрос не имели общей
   отмены. Сворачиваемые формы оставались смонтированными без признака активности.
3. `requestId` зависел от `captchaToken`, поэтому новый одноразовый токен менял
   ключ повторной заявки с теми же контактными данными.
4. Экран отправки с `z-index: 3` перекрывал крестики с `z-index: 1`.
   Это подтверждено реальным Playwright click-interception, исправлено для закрытия.
5. React #418/#423 воспроизводятся независимо от приложения. В изолированном
   документе с одним официальным виджетом повторно получены два исключения из
   `smartcaptcha.cloud.yandex.ru/react-with-dom-and-polyfills.18.2.0.min.js`.
   Это не HTTP 418 и не доказательство hydration mismatch нашего React-дерева.

## Что осталось у провайдера и ограничения

- #418/#423 остались. Для Yandex Cloud есть независимо повторяемый скрипт,
  UTC-время запуска, имя runtime, полные стеки и URL iframe без секретов/контактов.
- Официальный loader установленной версии кеширует даже неудачную загрузку SDK.
  Публичного retry/reset loader API нет. После ошибки/таймаута загрузки до появления
  API показывается явная кнопка «Обновить страницу»; обычный submit отключён, чтобы
  не создавать повторные бессмысленные ожидания. Это действие пользователя, не
  автоматическая перезагрузка. Ошибки уже загруженного виджета повторяются обычной
  кнопкой отправки. Сторонний низкоуровневый SDK-менеджер не добавлялся.
- Используется официальный React-компонент и его штатный destroy при unmount.
  Состояние между проверками сбрасывается удалением отработавшего виджета;
  автоматического создания следующего экземпляра в idle нет. Публичный reset
  ref компонент не предоставляет; [официальная документация](https://yandex.cloud/en/docs/smartcaptcha/concepts/react)
  описывает пересоздание для нового одноразового токена.
- Настоящий SDK загрузился и создал свои iframe после валидной отправки; тест
  остановился на проверке пользователя. Завершение настоящего интерактивного
  challenge человеком и получение server-verified токена не заявляются проверенными.
  Полная цепочка токен → серверное подтверждение подтверждена управляемым тестом.
  Боевые заявки не отправлялись, секретный ключ не выдавался клиенту.
- Локально установлен Next 16.3.0; зависимости/lock не обновлялись в рамках задачи.

## Выпуск

Production deployment не запускался; изменения SmartCaptcha остались локальными.
Для выпуска нужен обычный выпуск сайта после отдельного разрешения, без миграций
БД и без выпуска CMS. Перед выпуском — CI regression suite и release gate;
после — production-аудит с новым инвариантом и контролируемая ручная проверка
настоящего challenge. Не отключать серверную верификацию и не вводить тестовый
токен/обход защиты. При функциональном отказе реального challenge выпуск блокировать,
даже если независимые внутренние ошибки провайдера по-прежнему предупреждения.
