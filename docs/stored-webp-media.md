# Изображения без обработки на запросе

Новые изображения CMS уже конвертируются при загрузке: `Media.upload.formatOptions` задаёт WebP, качество 80; миниатюра также хранится в WebP. Пользователь может загрузить JPG/PNG/AVIF или готовый WebP. SVG и видео не перекодируются этим механизмом.

На публичном сайте и в CMS отключён оптимизатор Next.js. Старые вызовы `optimizedSrc` теперь возвращают адрес сохранённого файла, без `/_next/image`, параметров качества и выдуманных вариантов ширины. Раздельные изображения для мобильной и настольной версии сохраняются.

## Изображения из репозитория

`npm run images:prepare` запускается перед `dev` и `build`. JPEG/PNG/AVIF из `public` заранее конвертируются в `public/generated/webp`; существующие WebP, SVG и видео остаются как есть. Для фотографий — качество 85, размер до 2560×2560 без увеличения и обрезки. Для PNG сохраняются прозрачность и lossless-качество. Последовательности видеокадров исключены: у них уже есть отдельная проверенная lossless WebP-сборка.

Имена содержат хеш исходника и настроек. Повторная подготовка использует готовые файлы. `src/data/webp-assets.json` связывает старые адреса с WebP; старые адреса получают 308 на готовый файл. Например, ссылки с `.jpg` в сохранённом контенте продолжают работать. Исходники в репозитории не удаляются.

Статические импорты изображений в React также переведены на заранее созданные WebP. Для них подготовка создаёт файлы в `public/generated/imports`, а сборщик включает их как WebP в `/_next/static/media` с исходными размерами и данными предварительного просмотра. Промежуточные файлы импортов не дублируются в runtime-каталоге.

Первый проход: 757 файлов, 562,3 → 273,2 МБ. Это размеры заранее сохранённых файлов, без повторного кодирования во время просмотра. Docker упаковывает готовые файлы в `public-runtime`, исключая заменённые исходники из конечного образа. Хешированные WebP получают годовой immutable-кеш.

## Уже загруженные файлы CMS

`cms/scripts/convert-media-to-webp.ts` по умолчанию только перечисляет старые JPEG/PNG/AVIF. Запускать из папки CMS с её штатными переменными окружения:

```sh
node node_modules/tsx/dist/cli.mjs scripts/convert-media-to-webp.ts
node node_modules/tsx/dist/cli.mjs scripts/convert-media-to-webp.ts --apply --backup-dir=/private/backups/media-webp-2026-10-23
```

Для применения необходим отдельный абсолютный каталог резервной копии вне публичного хранилища. Перед заменой сохраняются запись и исходные файлы, проверяется отсутствие изменений записи. Обновляется тот же ID через Payload, поэтому связи проектов не меняются. Скрипт проверяет MIME и фактический формат результата. Старые имена записываются в `webp-redirects.json` на постоянном media-томе; запросы к ним перенаправляются в штатный защищённый endpoint нового файла.

Скрипт не выполнялся на production. Инвентаризацию через сохранённый ключ сайта CMS выполнить не удалось: сервер вернул HTTP 401. Количество старых форматов в production-хранилище пока не подтверждено. До миграции и проверки на сервере нельзя заявлять, что весь старый архив CMS уже перекодирован.

Конвертацию существующего архива следует запускать в техническое окно без параллельной замены тех же файлов в CMS.

## Проверка

Browser gate запрещает запросы `/_next/image`, используя настоящие файлы сайта. В нём больше нет обхода оптимизатора через перехват изображений. Отдельные тесты проверяют фактический WebP, прозрачность, повторное использование готовых файлов и совместимость старых URL.

Сборка CMS выявила блокирующую проверку уязвимой версии Next.js. Сайт и CMS обновлены до 16.4.3; Sharp закреплён на 0.35.5. Основание: [уведомление Next.js об обработке изображений](https://github.com/advisories/GHSA-2464-fhr4-w9xw) и [уведомление о Server Actions](https://github.com/advisories/GHSA-p3m5-59mp-jv5r). Обе production-сборки после обновления проходят.
