# PDF-паспорта проектов: локальный запуск

Система работает только после явного `PASSPORT_ENABLED=1`. Production не включён и не изменён. Существующая пилюля сохранена; по уточнению владельца контактный телефон остаётся обязательным. На локальном стенде заявка записывается в существующую PostgreSQL CMS с типом `test`, без внешней CRM и рассылок.

## Запуск

1. Существующий PostgreSQL: `docker start avgst-cms-postgres` (5433). CMS и сайт используют свои `.env.local`; CMS подключается к `avgst_cms`, SQLite не используется.
2. Установить зависимости Python 3.12: `py -3.12 -m venv passports/.venv`, затем `passports/.venv/Scripts/python -m pip install -r passports/requirements.txt` и `passports/.venv/Scripts/python -m playwright install chromium`. Linux: `python3.12 -m venv passports/.venv`, затем соответствующие `bin/python` и `playwright install --with-deps chromium`.
3. В обоих окружениях задать один абсолютный `PASSPORT_STORAGE_DIR`; каталог должен быть постоянным и доступным CMS для сигналов и отдельному worker для файлов. Не публиковать его как статическую папку. На локальном стенде: `D:/site-reserve-deploy/.local/passports`.
4. Сайт: `CMS_PUBLIC_URL=http://localhost:3001`, `CMS_SITE_API_KEY`, `PASSPORT_ENABLED=1`, `NEXT_PUBLIC_PASSPORT_CONCEPT=1`, `PASSPORT_PYTHON` с путём к Python venv. При использовании существующего установленного Chromium можно задать `PASSPORT_CHROMIUM_EXECUTABLE`; иначе Playwright использует собственный браузер.
5. CMS: её прежние `DATABASE_URL`, `PAYLOAD_SECRET`, `CMS_SITE_API_KEY`, `CMS_PUBLIC_URL=http://localhost:3001`, `CMS_SEED=0`, `CMS_MAINTENANCE=1`. Это отключает фоновые внешние автоматизации на стенде.
6. Для импортированных локальных копий установить в обоих окружениях `PASSPORT_LOCAL_CONFIG_BLOCK=import-local-ProjectConfig`. Этот override разрешён только с loopback CMS и вне production. Исходные локальные блоки не перезаписываются.
7. Запустить CMS: из `cms` команда `node node_modules/next/dist/bin/next dev --webpack --port 3001`. Сайт из корня: `node node_modules/next/dist/bin/next dev --webpack --port 3000`. Webpack используется из-за junction-зависимостей этого изолированного worktree.
8. Полная предварительная сборка всех опубликованных проектов обоих регионов: `node --env-file=.env.local cms/node_modules/tsx/dist/cli.mjs scripts/passports/worker.ts --once`. Для одного проекта добавить `--slug=ecohouse-128`.
9. Постоянный worker: та же команда без `--once`. Это отдельный процесс, не Next.js и не обработчик страницы. Для production позже понадобится супервизор/systemd и постоянный общий том; отдельный HTTP-сервис и дополнительная БД не требуются.
10. Открыть `/catalog/ecohouse-128`, выбрать регион, нажать существующую пилюлю и ввести телефон. После сохранения заявки выдаётся актуальный готовый PDF.

## Данные и цены

`resolver.ts` читает только структурированные CMS endpoints: опубликованный каталог, планировки, комплектации и настройки мессенджеров. Нормализатор цен использует `configurationTiers` и `tiersForRegion`; полная стоимость берётся из спеццены при её наличии, иначе из обычной цены. Чужой регион, дилерская цена и коэффициентные заглушки не используются. При отсутствии обязательной региональной цены паспорт не собирается.

Ипотечная база строго равна обычной региональной цене `standard`. Общие `calculateMortgage` и `monthlyPaymentForProject` используют текущие семейную программу, первоначальный взнос, срок, лимиты и рыночную ставку сайта. Расхождение с `ProjectHeroPayment` зафиксировано: первый экран выбирает минимум из ипотечных комплектаций. Его поведение не изменено. Если стандартная комплектация не самая дешёвая, суммы могут отличаться по явно заданному требованию PDF.

Матрицы сравнения импортируются из существующего `configuration-comparison/model`. Все строки, материальные характеристики и технические пояснения сохраняются; общие пояснения вынесены в широкие строки. Отсутствующие позиции каркасной матрицы явно отмечены «Уточняется», а не «Не входит». `sourceGaps` в снимке показывает неподтверждённые позиции. Это существующий пробел исходной модели, не новая спецификация строительства.

## Жизненный цикл

CMS hooks проектов, цен, блоков, медиа и глобальных настроек создают лёгкий сигнал. Worker читает сигналы раз в 2 секунды и дополнительно сверяет весь каталог раз в минуту. Цена NN меняет только NN fingerprint. Версия учитывает нормализованные данные, SHA-256 исходных изображений, контакты, региональные ссылки, исходники шаблона, матрицы, модель ипотеки и брендовые ресурсы. Дата генерации не вызывает ежедневную бессмысленную пересборку.

Задачи сохраняются как производные JSON-файлы, а не как второй каталог проектов. Создание одинаковой задачи атомарно и эксклюзивно. Один worker имеет lease с heartbeat; задачи тоже защищены lease. Зависшие lease восстанавливаются спустя 15 минут; renderer ограничен 10 минутами. Ошибки повторяются с экспоненциальной задержкой до 15 минут. Текущее и предыдущее содержимое CMS сверяется до и после рендера. Изменившийся во время сборки снимок не активируется.

Файлы: `documents/{slug}/{region}/{fingerprint}/passport.pdf`, `passport.html`, `snapshot.json`, `report.json`, `pages/page-NNN.png`. `latest.json` меняется атомарно только после успешного preflight. Файлы действующей версии не перезаписываются. Предыдущие версии сохраняются; автоматическое удаление архивов пока не включено.

Публичный download endpoint дополнительно заново вычисляет актуальную версию. При несовпадении выдаёт 503 и ставит обновление в очередь, не раздавая старую цену. Неопубликованный проект не выдаётся. Запрос готового файла не запускает Chromium. Доступ к файлу даёт краткоживущая HMAC-ссылка после сохранения контакта, с проверкой проекта и региона. Тип PDF, имя файла, ETag и приватное кэширование установлены явно.

## Проверки

- TS: `node --env-file=.env.local cms/node_modules/tsx/dist/cli.mjs --test tests/passport-pricing.test.ts tests/passport-storage.test.ts`.
- Python: `passports/.venv/Scripts/python -m pytest passports/tests -q`.
- Жизненный цикл на локальных импортированных копиях: `node --env-file=.env.local cms/node_modules/tsx/dist/cli.mjs scripts/passports/check-local-lifecycle.ts`. Скрипт ограничен localhost:5433/avgst_cms, восстанавливает изменённые цену и планировки в `finally` и не касается production.
- Preflight: опубликованность и полнота данных; три правильные комплектации; количество страниц `3 + variants`; точный A4 landscape; отсутствие переполнения DOM; минимальный текст 8 pt; изображения загружены и планы contain; текст всех помещений/площадей/характеристик/цен; встроенный Geist; кликабельные ссылки; декодирование обоих QR именно в канонический URL проекта.
- Каждый документ получает PNG всех страниц 180 dpi для визуального ревью. Подробную таблицу на смартфоне следует увеличивать; A4 landscape выбран по заданию ради четырёх колонок и планировок. Автоматическое уменьшение шрифта ниже 8 pt запрещено, неумещающийся проект блокируется.

## Переиспользование catalog

Изучены assembler/build/preflight/assets/pdf_optimize/qrcode_util, Chromium renderer, шаблоны и тесты. Переиспользован конвейер предварительная проверка → Jinja HTML → Chromium → PDF → PyMuPDF/PNG, внедрение изображений и отдельный процесс с `--disable-dev-shm-usage`. QR переделан в SVG с quiet zone 4 модуля и обязательным декодированием. Защита загрузчика усилена: точный allowlist origins, запрет redirect/приватных IP, DNS pinning, лимиты размера/времени. Фотографии оптимизируются JPEG 90, чертежи остаются lossless. Старые Tilda, SQLAlchemy, Gilroy, модели/базы каталога и UI не перенесены.
