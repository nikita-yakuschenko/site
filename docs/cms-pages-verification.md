# Режим проверки редактора страниц CMS

## Порядок работы

1. Снять read-only индекс всех записей `/pages`: ID, название, маршрут, статус, упорядоченные блоки, типы, ссылки на общие блоки и формы.
2. Сопоставить каждый блок с текущим публичным компонентом, его текстами, изображениями и редактируемыми частями. Зафиксировать исходные значения до изменений.
3. Проверять блоки последовательно по страницам. Общий блок реализовывать и проверять один раз, затем проверять каждое место его использования.
4. Сложные секвенции производства оставить отдельным именованным блоком структуры без редактора их содержимого.

## Матрица приёмки

Для каждой пары «страница — блок» фиксировать:

- **Название:** русское название в списке, селекторе типа, составе и заголовке превью; нет программных имён вместо подписей.
- **Состав:** все фактически существующие тексты, кнопки, изображения, галереи и формы перечислены; нет пустого состава у содержательного блока.
- **Превью:** выбор блока открывает именно его; выбор части указывает соответствующий элемент; нет заглушки неподключённого превью.
- **Редактор:** открывается правильная запись, поля содержат текущие значения; используются существующие текстовые поля, кнопки и загрузчики изображений редактора проекта.
- **Сохранение:** правка сохраняется после повторного открытия; отдельное превью и полная страница читают одинаковые данные.
- **Публикация:** изменение опубликованного значения появляется на соответствующей странице сайта; черновик не меняет опубликованную страницу.
- **Сохранность:** исходные тексты, изображения, порядок, ссылки и настройки сохраняются при начальном подключении CMS.
- **Источники данных:** счётчики, фильтры и значения, уже получаемые из базы, продолжают рассчитываться из неё. Сохранение обложки или текста не должно заменять их сохранённой строкой. Для «Подборок» отдельно сверять четыре счётчика с каталогом и сохранять действующий редактор выбора серии.

## Автоматические проверки

- Проверка полного покрытия индекса: каждому типу блока соответствует русское название, описание состава, редактор и публичный/изолированный рендерер либо явное исключение производственных секвенций.
- Контрактные тесты на применение сохранённых текстов, кнопок и медиа к публичным компонентам, включая пустые строки, отключённые части и отсутствующие значения.
- Проверка идемпотентного заполнения: повторный запуск не перезаписывает отредактированные значения и не создаёт дубли.
- TypeScript и ESLint в обоих приложениях; тесты CMS и относящиеся к изменению браузерные сценарии.

## Браузерная проверка

- Открыть каждую страницу из индекса, раскрыть каждый блок, проверить состав и выбор в превью, открыть его редактор.
- На тестовой копии данных изменить текст, подпись/ссылку кнопки, одиночное изображение и порядок галереи; сохранить, открыть заново, проверить отдельное превью и полную страницу.
- Проверить сохранение блока и повторное открытие. У страниц и проектов, где есть черновики, отдельно проверить их публикацию. Общие блоки сейчас сохраняются непосредственно, без отдельного черновика. Не публиковать тестовые маркеры, не отправлять реальные заявки, не менять рабочие настройки интеграций.
- Production: безопасное заполнение только отсутствующих исходных данных, контроль количества записей и исходных значений; проверка страниц и превью после выпуска.

## Отчёт

Индекс и матрица должны различать: проверено кодом, проверено в браузере, проверено сохранением/публикацией, исключение, ещё не проверено. Успешная сборка сама по себе не означает готовность редактора.

## Команды повторной проверки

Из корня проекта, при работающих локальных сайте, CMS и PostgreSQL:

```powershell
node scripts/check-cms-page-content.mjs
node scripts/check-cms-page-previews.mjs
```

Первая команда запрещает production-адреса, меняет по одному полю каждого подключённого блока, проверяет сохранённую запись и DOM страницы, затем возвращает исходное значение. Отчёт: `docs/cms-page-content-check.json`.

Вторая команда проверяет русские названия и реальное изолированное превью всех размещений из списка страниц. Переадресации учитываются отдельно; готовый дом проверяется на записи типа «Готовый дом», если она есть. Отчёт: `docs/cms-page-preview-check.json`.

Заполнение текущими значениями выполняется отдельно, сначала без записи:

```powershell
cd cms
npx tsx scripts/sync-page-content.ts --input=data/page-content-baseline.json --assets=D:/site/public
```

Флаг `--apply` разрешает запись. Повторное заполнение сохраняет значения уже существующих ключей. Производственные секвенции не получают полей содержимого. Данные конкретных проектов остаются в редакторе проекта; кнопка из структуры ведёт к тому же проекту, который выбран для примера в превью.
