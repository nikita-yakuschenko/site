# Исправления: измеримость, отказы CMS и первые изменения SSR

28 октября 2026 года. Работы выполняются по разрешению пользователя «Приступай пошагово» после диагностического аудита. Исходный аудит в `docs/audit/` описывает прежнее состояние и не переписывался. Полная приёмка производительности ещё не завершена.

## Выполнено

1. **Идентификация и диагностика.** Prebuild формирует `build/identity.json`; Next BUILD_ID и `/api/health` используют один идентификатор. Хеш учитывает исходники, конфигурацию, исходные public-файлы, публичные build-переменные и runtime сборки. APP_COMMIT/GITHUB_SHA или локальный Git дают revision. При сборке без Git revision нужно передать через существующий Docker ARG APP_COMMIT; автоматическая передача платформой не предполагается. `sourceDirty: null` означает отсутствие данных, а не чистое дерево. Это fingerprint входов сборки, не digest контейнера.
2. **Безопасные логи.** Proxy выдаёт UUID запроса, не доверяя входному идентификатору. Обёртка CMS фиксирует операцию, шаблон маршрута, статус, причину ошибки, длительность и build ID. Успешные обращения логируются от 500 мс; `CMS_REQUEST_LOGS=all` включает остальные. Секреты, тела ответов, произвольные сообщения ошибок и query-параметры не выводятся. `cachePolicy` показывает настройку, а не фактический HIT/MISS. Framework control flow сохраняется через `unstable_rethrow`.
3. **Деградация каталога.** Ошибка CMS, отсутствие ключа и некорректный ответ больше не становятся пустым успешным каталогом или ложным отсутствием существующего проекта. Добавлен экран ошибки с повтором. Настоящий отсутствующий slug сохраняет 404. Информационные страницы переживают недоступность необязательного каталога в оболочке. `/api/catalog/availability` при ошибке возвращает 503.
4. **Readiness.** `/api/health` остаётся проверкой процесса. Новый `/api/ready` проверяет контракт каталога через отдельный no-store запрос с таймаутом 2,5 с. Одновременные пробы объединяются, результат переиспользуется 2 с. При отказе — 503, при работоспособном каталоге — 200. Настройки production healthcheck не менялись.
5. **SSR и навигация.** Независимые чтения настроек, контента и каталога в layout запускаются вместе. На странице проекта независимые группы секций, реакции, порядок и похожие проекты также запускаются параллельно. Внутренние ссылки карточек заменены на Next Link с `prefetch={false}`. Стили и порядок контента сохранены.
6. **Проверки.** Добавлены unit-тесты, локальные сценарии отказов/восстановления и воспроизводимая модель SSR. Unit и resilience проверки добавлены в существующий CI workflow. Из lint исключены сгенерированные диагностические отчёты; исправлены два имени переменных и локальная проверка даты в Server Component без изменения бизнес-условия. Глобальные полезные lint-правила не отключались.

## Контролируемая модель задержки

На том же Windows host, Node 22.13.1, локальный mock CMS с задержкой каждого ответа 250 мс. По пять повторов; 30 запросов суммарно для задержек 0/250 мс и трёх маршрутов. Это локальная модель, а не production/Core Web Vitals. Старый запуск использовал `next start`, новый — standalone; среда общая, не выделенный benchmark host. Сравнение показывает изменение критического пути, но не гарантирует такой процент ускорения production.

Эта серия выполнена до последних изменений, затрагивающих только lint и CI; итоговая сборка и функциональные проверки повторены после них. Целевой TTFB ≤400 мс **не достигнут**.

## Статус backlog и ограничения

- B01/F05: локальные основные сценарии отказа и восстановления проверены. Кеширование 60 с сохранено; не введено хранение старых цен. Некорректный HTTP 200 может сохраняться в Next Data Cache до истечения срока: немедленное восстановление после такого ответа не обещается. Warm-cache freshness matrix остаётся отдельной работой B11.
- B02/B08/F11/F13: добавлены идентификатор сборки, безопасная диагностика CMS и framework errors. Доставка revision в production, агрегированные counters, RUM, реальные cache outcomes и browser/server correlation вне этой локальной проверки ещё не приняты.
- B04 выполнена; B09 частично: независимые фазы параллельны, но все секции пока ещё ожидаются перед возвратом страницы. Streaming hero отдельно не введён.
- B05/F03 **остаётся**: оболочка читает полный каталог ради boolean, а серверная граница NotFound по-прежнему читает рекомендации. Отказ сделан безопасным, стоимость чтения ещё не устранена.
- B22/F17: обычный desktop/mobile click, Back, регион и избранное проверены. Analytics lifecycle, consent/preview и все варианты modified click не объявляются полностью проверенными.
- B07/F12: штатный lint завершился с exit 0. Существующие предупреждения, преимущественно про `<img>`, сохранены.
- B17: endpoint и локальный synthetic реализованы. Подключение мониторинга/оркестратора production ещё не выполнено.
- Статус HTML-ошибки зависит от момента streaming: локальные прямые холодные запросы дали 500; при уже отправленных заголовках Next может сохранить 200. 503 гарантируется проверенными JSON endpoints readiness/availability.
- Медиа, шрифты, общий CSS/client manifest, SQL/DB, freshness SLA, инфраструктура и полноценные production CWV/RUM остаются следующими этапами. Dependencies, production-конфигурация, содержимое CMS и БД не менялись. Новая версия не развёрнута.

## Воспроизведение

Сборку выполнять в отдельной копии: prebuild обновляет производные media/index-файлы. Здесь использована `D:/site-remediation-20261028` без `.env` и production-секретов, с существующими зависимостями и подготовленными media. Исходная копия аудита не изменена.

```powershell
# Из D:/site — проверки исходников
npm run test:server
npx tsc --noEmit --incremental false
npm run lint

# В изолированной копии, Node 22.13+; без CMS_SITE_API_KEY
$env:NEXT_TELEMETRY_DISABLED='1'
$env:BROWSER_DIAGNOSTICS_FIXTURE_CATALOG='1'
$env:CMS_PUBLIC_URL='http://127.0.0.1:9'
$env:APP_COMMIT='c544500b9a80946deb53829e5942053c1d78f5bc'
npm run build

# Снова из D:/site; локальные mock-сервисы запускаются самим runner
node scripts/check-cms-resilience.mjs D:/site-remediation-20261028 D:/site/docs/remediation/artifacts
node scripts/check-ssr-critical-path.mjs D:/site-remediation-20261028 D:/site/docs/remediation/artifacts
```

Текущие результаты: [runtime](artifacts/step-01-runtime.json), [SSR](artifacts/step-02-ssr.json), [сохранность входов](artifacts/preserved-inputs.json). `step-01-first-pass.json` — ранний промежуточный прогон с неверно вычислявшимся elapsedMs; для численных выводов не используется. Логи сборки, TypeScript, lint и unit сохранены локально рядом, но исключаются существующим правилом `*.log` из Git. CI сохраняет runtime-артефакты отдельно; удалённый workflow в этой работе не запускался.
