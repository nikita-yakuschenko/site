## Подтверждённые проблемы самого стенда

1. **Нет изоляции локальной сборки.** В trace Chromium desktop зафиксирован ответ `308` на `http://127.0.0.1:3000/catalog/finlyandiya-149` с `Location: https://avgst.ru/catalog/finland-149`; следующий документ — production с `200`. `managedRedirect()` берёт живой публичный реестр CMS и собирает абсолютный адрес на `https://avgst.ru`. Одного fixture-каталога недостаточно для изоляции.
2. **Ключ капчи не подходит домену CI.** В трёх сценариях записано `[SmartCaptcha] Widget with this key cannot be used in the host: 127.0.0.1:3000`. Workflow забирает site key с production и запускает его локально.
3. **Ошибка подсчёта частоты.** `Finding.browser` содержит `webkit`/`chromium`, а `Run.browser` — `webkit-desktop` и т. п. Кроме того, `Run.scenario` содержит `@critical`, а `Finding.scenario` — нет. Знаменатель оказывается нулевым и заменяется единицей. В сохранённом summary есть **200%**. Эти проценты непригодны даже как частота синтетических прогонов.
4. **Неполный классификатор отмены запросов.** Игнорируются `net::ERR_ABORTED` и `NS_BINDING_ABORTED`, но WebKit `Load request cancelled` становится critical для JS. Отмену нужно привязывать к жизненному циклу навигации, иначе можно как получить ложное падение, так и скрыть настоящую ошибку чрезмерно широким исключением.
5. **Мобильный сценарий устарел относительно main.** Тест дважды нажимает `.cfilter__toggle`, предполагая «сброс, затем открыть». В актуальном main кнопка только открывает/закрывает панель, сброс отдельный. Простое перенесение тестов приведёт к новым ложным падениям.
6. **Проверка цен допускает пустые данные.** `.project-config` читается через `catch(() => '')`, сравнение выполняется только при непустых строках. Для надёжного теста нужны проект с известными региональными ценами, обязательное наличие блока и проверка конкретной цены.
7. **Ежедневный production audit ещё не введён.** Workflow остался в ветке PR, отсутствует в main. Плановое выполнение не работает. Последний release workflow упал, PR остаётся открытым.

## Что известно о SmartCaptcha

В четырёх неуспешных сценариях последнего CI есть React #418. Стек указывает на `https://smartcaptcha.cloud.yandex.ru/react-with-dom-and-polyfills.18.2.0.min.js`; также встречается #423. Источник исключения установлен, первопричина и влияние на успешную отправку заявки не установлены.

Нельзя переносить вывод о причине с локального недопустимого host на production. Более ранняя документация сообщает о воспроизведении на production, поэтому после исправления стенда нужен отдельный актуальный прогон на разрешённом домене.

Проверка валидной заявки отсутствует по замыслу тестов: они открывают форму и отправляют невалидные поля. Работоспособность цепочки «валидная капча → сервер → CRM» этими отчётами не доказана.

## Выполненные исправления стенда

После разбора ветка объединена с актуальным `origin/main`. Workflows переведены с контейнера на Ubuntu 24.04 с установкой браузеров из lockfile и отдельной проверкой запуска. Исправлены группировка по профилю, формула частоты и классификация отмен при переходе. Добавлены регрессионные тесты отчётности.

Локальная проверка использует каталог и региональные комплектации с фиксированными ценами; публичные CMS-редиректы отключены только в этом режиме. Уход на другой origin считается ошибкой. SmartCaptcha заменяется исключительно в браузере локального теста; production audit оставляет настоящий виджет. Сервер не принимает тестовые токены. Мобильный сценарий использует актуальную кнопку сброса, региональный сценарий требует наличие комплектаций и проверяет цены 2 000 000 → 2 500 000 ₽ вместо необязательного сравнения пустых строк.

Production и ветка main этими изменениями не обновляются. Ежедневное расписание начнёт работать только после принятия PR. Успешная серверная отправка заявки и CRM остаются отдельной непокрытой проверкой.

## Проверка исправлений, 23 октября

Локальная production-сборка: 25/25 критических сценариев прошли во всех пяти профилях. TypeScript, ESLint изменённых модулей и три регрессионных теста отчётности прошли.

Отдельный полный прогон `https://avgst.ru` с настоящей капчей: 30 сценариев, 10 прошли, 20 завершились неуспешно. В 19 неуспешных сценариях зарегистрирован React #418 со стеком SmartCaptcha; дополнительно в Firefox встречается отказ загрузки чанка провайдера. Один сценарий Firefox завершился таймаутом `load` на `/catalog/scandy-106`. В WebKit mobile дополнительно зарегистрирован `TypeError: Load failed` во время перезагрузки; причина пока не установлена. Эти числа относятся к синтетическим сценариям, не к посетителям и не к числу отдельных дефектов.

По этому прогону уточнены источник ChunkLoadError и учёт отмен запросов предыдущего документа: запоздавшая отмена после завершения новой загрузки не считается отказом её CSS. Неопределённые `Load failed` и реальные ошибки провайдера не подавляются. Артефакты полного прогона сохранены локально в `diagnostics-results/production-first/`.
